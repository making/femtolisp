# Deleted todo items

A row is added when a `.todo/NNN-*.md` file is removed, recording the commit that
removed it. `Status` is exactly `completed` or `cancelled` -- no prose. `Model` is
the model that did the WORK, not the one that removed the file (an item outlives its
author); for work done by a subagent it is that subagent's own model -- the
`Co-Authored-By` trailer it inherits from the orchestrating session is a hint, not
the answer.

## Duplicate numbers

Numbers come from `.todo/claim-number.sh`; its header comment and CLAUDE.md,
"Working Alongside Other Sessions", hold the claiming mechanics. A claim whose item
is never filed leaves a gap; gaps are fine, reuse is not.

If a duplicate turns up anyway, **the side with a LIVE file renumbers** -- a recorded
row cannot move, because it names the path inside the commit that removed it. If both
files are still open, the later commit's side moves. Renumber with `git mv` and
re-point every `.todo`/`.kb` reference. Read a row by its full file name, never its
number alone.

## Where the artefacts live

**A `.todo/NNN-*.md` file is the item; its measurement artefacts are
`.todo/artefacts/NNN-title/`.** So the top level of `.todo/` lists open items and nothing
else, and a listing answers "is this open" without opening anything.

An item is deleted when it closes and its artefacts are kept forever, because the numbers
outlive the item that produced them. They shared one namespace until 2026-09-06, and three
people read `672`'s directory as an open item hours after it closed -- one nearly held a
rename on it. `PathCitationTest.theTodoDirectoryHoldsNoItemNumberedDirectories` keeps the
two apart; nothing has to be remembered, and closing an item moves nothing.

## Reading a deleted item

`Commit` is the commit that REMOVED the file, so `git show <Commit>~:<File>` recovers
the content -- every row must keep this invariant. Each `Commit` cell is linked as
`https://github.com/making/rontolisp/blob/<commit>~/<file>`.

## Recording a deletion

Rows live in monthly files `.todo/history/YYYY-MM.md` -- append there (create a new
month by copying an existing file's header and table shape, and link it below).
**Appending the row is the whole job.** The index carries no counts: a count can only
be written from a read that missed a concurrent append, so it drifts silently --
count the rows if you want a count.
